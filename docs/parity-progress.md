## Implementation Notes

- `pkg/document` now owns document sessions, edit overlay, window reads, save, find, contains-filter, stable multi-column sort, and view mapping.
- `pkg/document` now includes full-record snapshot history for first-pass undo/redo and materializes row/column structural edits into temporary working copies so the original file is not modified before Save.
- `pkg/document.MoveRow` and `pkg/document.MoveColumn` provide adjacent row/column movement. Data rows cannot move above a detected header row, boundary moves are clean no-ops, and successful moves are undoable.
- `pkg/document.PasteRows` and `pkg/document.PasteColumns` provide undoable row/column copy-or-cut insertion through `/api/row/paste` and `/api/column/paste`, with backward-compatible single-row/single-column request fields plus `sourceRows`/`sourceCols` arrays. Frontend `Copy Row`/`Copy Column` seed an internal structural clipboard from the active row/column selection, while `row.cut`/`row.paste` and `column.cut`/`column.paste` are available from Command Palette and context menus.
- `pkg/document.HideRow` hides source rows through the existing view-row mapping without changing dirty state. Frontend hidden columns use a visible-to-source column mapping so edits, copy, profile, filters, sorting, and transforms still target source columns correctly. The Inspector/context menus expose a command-backed restore for all hidden columns without clearing filters or sorts, and Command Palette/context menus expose a row-only restore that clears the active row view while preserving hidden columns.
- `pkg/document.EditCells` and `/api/edit-batch` apply multi-cell edits as one undoable operation.
- `pkg/appserver` delegates document behavior to `pkg/document` instead of owning session logic directly.
- `csvcore.RecordWindow` now includes `sourceRows` so UI edits can target the original source row even when a filtered/sorted view is active.
- `pkg/sqlexpr` provides the first SQL WHERE expression engine for row filters: identifiers/header names, `c1` columns, comparisons, `AND`/`OR`/`NOT`, `LIKE`, `IS NULL`, arithmetic, `CAST`/`TRY_CAST`, exact bigint literals/casts/comparisons for values above JavaScript's safe-integer range, core string/numeric/conditional functions, typed date/time/timestamp literals, temporal +/- interval arithmetic, temporal subtraction to intervals, and first-pass interval literals/casts with signed composite quantities and field precision qualifiers.
- `pkg/protocol` parses official-style goto locations plus both `smoothcsv://file/...` and `opencsv://file/...` URLs, including row/cell/range locations and case-insensitive shared format query parameters such as `quotemode`, `lineending`, `headerrows`, and `headercolumns`.
- Root CLI syntax now accepts official-style `opencsv [options] [path ...]`, `--goto`, `--diff`, `--delimiter`, `--encoding`, header flags, window flags, `--wait`, `--version`, and `--help` while retaining developer subcommands. The `opencsv grep` subcommand emits JSON cell matches with case-insensitive, regex, column-targeted, and limited-result options.
- CLI open applies delimiter, encoding, line ending, quote character, quote mode, and header-row overrides to `csvcore.OpenDocument`.
- CLI/API/URL open now propagate `header-columns`/`headerColumns` into CSV dialect metadata and `line-ending`/`lineEnding` into line-ending metadata. The frontend shows delimiter, header-column count, and line ending in format status and preserves them in saved/imported/exported format presets.
- Browser URL boot-open now applies `delimiter`, `quote`, official `quotemode`, `quote-mode`, `quote-escape`, `encoding`, official `lineending`, `line-ending`, and header query params to `/api/open`, with explicit URL params taking precedence over matched format rules.
- Browser URL boot-open now applies 1-indexed `goto`, `location`, `range`, or `row`/`col`/`endRow`/`endCol` query params to the grid selection and scroll position.
- Browser URL boot-open now accepts `find=` plus optional `findRun=1` to prefill and run Find after a file opens, mirroring the existing SQL/Profile/Diff URL-run verification pattern for local deep-link workflows.
- Frontend grid scroll positions persist per local file path in a bounded browser store and restore during document load, with explicit URL locations still able to override the restored viewport.
- Find now supports regex/case/whole-cell options, total match counts, offset/limit result windows, request-context cancellation, and streaming scans for clean UTF-8/UTF-8-BOM files with standard double-quote escaping in the API layer. Replace current/all stores edits through the document edit overlay and marks the session dirty, while replace preview returns the same proposed changes without mutating the document or pushing undo history.
- Frontend Find/Replace now exposes `Aa`, `=`, and `.*` toggles for case-sensitive, whole-cell, and regex modes, and sends those options to `/api/find` and `/api/replace`.
- Frontend Find now caches the current result window, shows `current/total`, and supports Previous/Next navigation from the toolbar and Enter/Shift+Enter in the query field. Large match sets page through `/api/find offset` instead of trapping navigation in the first loaded result window.
